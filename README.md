# Multi-Agent Delivery — نظام توصيل ذكي بالـ ACO + Supervisor Agent

مشروع مادة Agent-Based. نظام Multi-Agent بيوزع الطلبات على المناديب ويحدد مسار كل مندوب بخوارزمية **Ant Colony Optimization**، وبيعيد التخطيط لما يحصل أي تغيير أثناء التشغيل (طلب جديد، إلغاء، زحمة، عطل مندوب) من غير ما يمسح اللي اتعلمه (الـ pheromone بيتحفظ).

## التشغيل
```
pip install numpy matplotlib      # matplotlib اختياري (للرسومات)
python gui.py                     # الواجهة (tkinter جاي مع بايثون على ويندوز)
python main.py demo               # تشغيل سريع من غير واجهة
python experiments.py all         # كل التجارب + الرسومات + التقرير (حوالي 6 دقايق)
python experiments.py compare --runs 3   # نسخة سريعة
python report.py                  # يعيد بناء التقرير من النتايج الموجودة
```
أول تشغيل بيولّد 6 سيناريوهات CSV ثابتة في `data/` (عشان نفس السيناريو يتكرر وقت المقارنة).

## الـ Agents
| Agent | الدور |
|---|---|
| **Supervisor** | الأعلى. بيستقبل الطلبات والإلغاءات والأعطال وتقارير الزحمة، بيقرر **امتى** الـ Dispatcher يخطط، بيسأل المناديب عن مكانهم قبل كل خطة، بيراجع الخطة، ولو متوقع تأخير بيطلب بحث أعمق، وبيكتشف خطر التأخير من تحديثات المواقع. |
| **Dispatcher** | بيخطط ويوزع المسارات (ACO / أقرب عميل / GA / SA) ويحتفظ بالـ pheromone. |
| **Courier ×8** | سعة 3 وسرعة وموقع، بينفذ المسار وممكن يتعطل. |
| **Customer** | بيبعت الطلب أو يلغيه ويأكد الاستلام. |
| **Traffic** | بيبطّئ طرق في مناطق زحمة. |

## الإضافات الجديدة
1. **Ablation للـ Supervisor:** مقارنة 3 سياسات: `full` / `no_risk_escalation` / `fixed_timer` (بيخطط كل 30 دقيقة بس) على السيناريوهات الديناميكية 4 و5 و6. بتثبت إن الـ Supervisor له فايدة بالأرقام.
2. **مقارنة مع Genetic Algorithm و Simulated Annealing** (`metaheuristics.py`) بنفس ميزانية التقييمات (نمل × دورات) ونفس الـ local search الأخير.
3. **إحصاء:** mean ± std و min-max و 95% CI لكل سيناريو.
4. **أحداث أصعب (سيناريو 6):** عطل مندوب وإلغاء طلب، والـ Supervisor بيعيد توزيع الطلبات العالقة.
5. **Live compare في الواجهة:** نظامين جنب بعض على نفس السيناريو، والأحداث (طلب/زحمة/عطل/إلغاء) بتتطبق على الاتنين.
6. **تقرير تلقائي:** `results/report.html` و`report.md` (افتح الـ html في Word واحفظه docx).

## الخوارزمية
- كل نملة بتبني مسارات المناديب واحد ورا التاني (بتحترم السعة)، واختيار العميل التالي = pheromone × (1 / (مسافة + عقوبة تأخير متوقع)).
- التكلفة = المسافة + 0.5 × دقايق التأخير + 15 × عدد التسليمات المتأخرة.
- تبخر 0.3، تعزيز لأحسن حل في الدورة وأحسن حل كلي، 5% اختيار عشوائي، وlocal search (نقل/تبديل).
- عند إعادة التخطيط: المندوب بيكمل هدفه الحالي، والباقي بيتوزع من جديد بنص عدد الدورات ونفس الـ pheromone.

## خطة العرض للدكتورة
1. `python gui.py` ← سيناريو 5 أو 6 ← Start، وركّز على Supervisor feed.
2. **+ New order** واضغط على الخريطة، ثم **Traffic jam**، ثم **Breakdown**: المسارات بتتعدل في ثواني.
3. **Live compare**: ACO جنب Nearest customer على نفس السيناريو.
4. اختار Supervisor policy = `fixed_timer` وقارن مع `full` (دي الـ ablation).
5. في الآخر جدول `results/summary.md` وجدول الـ ablation.

## ملاحظات وتبسيطات
- العميل له طلب واحد، والسعة = أقصى عدد طلبات متعينة للمندوب في نفس الوقت.
- الوحدات: خريطة 100×100، الزمن بالدقيقة، السرعة وحدة/دقيقة. البيانات synthetic (محاكاة).
- لو الحل بيقف على مسار مش كويس زوّد `rho` أو `ants` أو `explore` في `ACOParams`.
- GA وSA ما اتعملهمش tuning بنفس مجهود ACO، وبياخدوا نفس عدد التقييمات مش نفس الزمن (هما أسرع بكتير).
